# 커밋메시지 규칙

이모지 의미는 `_etc/_GIT_EMOJI_RULE.md` 를 따른다.  
사용자가 **커밋메시지** 라고만 하면 `git commit` 하지 말고 `_etc/_COMMIT_MESSAGE.md` 에만 적는다. 실제 커밋은 사용자가 커밋을 요청했을 때만 한다.

## 형식

```
YY.MM.DD :emoji: 한 줄 요약

:emoji: [Client] Area: 짧은 한글
:emoji: [Server] Area: 짧은 한글
```

- 날짜는 작업일 기준 `YY.MM.DD`
- 첫 줄은 제목. 이모지 하나 + 짧은 한글 요약
- 관련 작업이 둘이면 제목에서 ` / ` 로 이어도 된다
- 빈 줄 다음이 본문. 한 줄에 논리적인 작업 하나
- 본문 줄 끝 마침표는 쓰지 않는다

## 제목 이모지

이번 커밋의 **대표 성격** 하나만 고른다.

- 새 기능 → `:sparkles:`
- UI/색/레이아웃 → `:lipstick:`
- 자잘한 기능 수정 → `:wrench:`
- 구조 개편 → `:building_construction:`
- DB → `:oil_drum:`

## 본문 한 줄 구성

` :emoji: [Client|Server] Area: 내용 `

1. **이모지**는 그 줄의 성격에 맞게 `_GIT_EMOJI_RULE.md` 에서 고른다
   - 파일/기능 추가 → `:heavy_plus_sign:`
   - 타입 추가·수정 → `:label:`
   - 작은 연결/수정 → `:wrench:`
   - 새 동작 → `:sparkles:`
   - UI → `:lipstick:`
   - 이름 변경 → `:pencil2:` (타입은 `:label:`)
2. **`[Client]` / `[Server]`** 를 이모지 다음에 붙인다. 클라이언트·서버가 섞이면 줄을 나눈다
3. **Area** 는 어디인지 짧게. 예: `Theme`, `Ultimate`, `PitchRecord`, `Modal`, `Redux`, `LocalTypes`, `Template`
4. **내용** 은 무엇을/왜 인지 짧게. 파일 경로 나열, “변경했습니다” 같은 말은 쓰지 않는다

## 작성 전에

- `git status` / `git diff` / 최근 커밋 메시지를 본다
- **지금 워킹트리에 남은 변경**만 적는다. 이미 커밋된 내용은 넣지 않는다
- 주석 처리, 커서 주석 같은 잡음은 본문에 넣지 않는다
- 커밋 메시지 파일(`_etc/_COMMIT_MESSAGE.md`) 자체는 커밋에 넣지 않는다

## 예시

```
26.10.26 :sparkles: 얼티 선수 이름 더블클릭으로 desc 수정

:heavy_plus_sign: [Client] Redux: Modal Slice 에 얼티 선수별 메모 추가
:label: [Client] LocalTypes: EditUltiRecordDesc 모달 타입/페이로드 추가
:heavy_plus_sign: [Client] Modal: EditUltiRecordDescModal 추가
:wrench: [Client] Template: 얼티 선수 desc 모달 연결
:sparkles: [Client] Ultimate: 수정모드가 아닐 때 이름 더블클릭으로 desc 모달
:lipstick: [Client] Ultimate: 선수 이름 칸 커서 표시
```
